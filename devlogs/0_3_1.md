# Oblada 0.3.1: devlog

Not released yet. Based on Chromium 156.0.8078.48. What changed since 0.3.0, in detail; the
public release notes are in [`changelogs/0_3_1.json`](../changelogs/0_3_1.json).

## Performance

Changes to Chromium's defaults that other Chromium browsers make too (Helium, Brave,
Thorium), to start faster and do less in the background.

- **Restored tabs load when opened**, as in Firefox and Zen. After a restart, Chromium's
  `BackgroundTabLoadingPolicy` loads the restored tabs in the background a few at a time (at
  least 4, up to 20, by memory and age); `ShouldLoad()` in
  `chrome/browser/performance_manager/policies/background_tab_loading_policy.cc` now only lets
  it load those showing, pinned ones (the Essentials, `IsPinnedTab()`) and those that work in
  the background (`UsesBackgroundCommunication()`: notifications allowed, or a title or icon
  that changes while hidden, such as chats and mail). The others are left unloaded, with their
  icon fetched from history as before, and load when activated, as tabs past Chromium's limit
  always did. Helium does the same in a larger patch.
- **Memory Saver is on by default** (`kMemorySaverModeState` registered as `kEnabled` in
  `components/performance_manager/user_tuning/prefs.cc`), as in Helium: tabs left alone are
  discarded and reload when opened. Settings > Performance turns it off; it's a Local State
  pref, so it applies to people who never changed it.
- **Discarded tabs stay in their container.** On desktop Chromium discards a tab by replacing
  its WebContents with an empty one (`TabLifecycleUnit::FinishDiscard()` in
  `chrome/browser/resource_coordinator/tab_lifecycle_unit.cc`), created from the profile alone:
  a container tab came back outside its container when reloaded, and the last tab of a
  temporary container made it look unused, so it was removed with its data. This already
  happened when memory ran low, or with an extension's `tabs.discard()`. The new contents now
  get the tab's container (`oblada::containers::SiteInstanceForDiscardedTab()`).
- **Downloads use parallel connections** (`kParallelDownloading` on everywhere, in
  `components/download/public/common/download_features.cc`), as Chromium already does on
  Android and Thorium on desktop: large files come over several connections where the server
  allows ranges.
- **No Journeys** (`kJourneys` off, `components/history_clusters/core/features.cc`), as in Brave
  and Helium: it clustered every visit as pages loaded, for History's "By group" view and the
  address bar's suggestions of those groups.
- **No `PageResourceMonitor`**
  (`chrome/browser/performance_manager/chrome_browser_main_extra_parts_performance_manager.cc`),
  as in Brave: every two minutes it measured every page's CPU and memory, and the system's
  CPU, only for Chrome's UKM metrics, which Oblada doesn't send. Brave also empties Chromium's
  metrics providers; Oblada doesn't need to, since non-Google builds never start metrics
  recording (`MetricsServiceAccessor::IsMetricsReportingEnabled()`).
- **Components downloaded when used.** Some of Chromium's components came down for everyone:
  - Live Caption's speech recognition (SODA, some 220 MB with a language):
    `SodaInstaller::Init()` (`components/soda/soda_installer.cc`) installed it at every start
    when it was used in the last 30 days, and installing pushed its removal 30 days on, so
    after one use it stayed forever. It's now installed at startup only while a feature using
    it (Live Caption) is on; sites using on-device speech recognition install it when they
    need it. (Its first download had come from `PreemptiveSodaDownload`, on in the field trial
    testing config of builds before `disable_fieldtrial_testing_config`.)
  - Read aloud's voice engine (WasmTtsEngine, some 25 MB) was registered at every start
    (`chrome/browser/component_updater/registration.cc`). `RegisterWasmTtsEngineComponent()`
    now registers it only if Reading mode was opened (its last opening,
    `kAccessibilityReadAnythingDateLastOpened`, which Chromium clears after 90 days), and
    removes an engine installed earlier otherwise; Reading mode registers it when it opens
    (`WasmTtsEngineComponentInstallerPolicy::RegisterAndUpdateOnDemand()`, from
    `ReadAnythingService::SetupDesktopEngine()`).
  - Screen AI (text recognition in PDFs, Reading mode) was already downloaded only when used,
    and removed after 30 days unused.
  - The component updater keeps a copy of each component's package in `component_crx_cache`,
    for smaller updates, without limit: for these large components it doubled the space. Their
    installer policies (SODA, its language packs, Screen AI, WasmTtsEngine) now return false
    from `AllowCachedCopies()`, as Chromium's AI models do; existing copies go at their next
    update.
- Official builds (PGO, ThinLTO) for releases are planned in [`TODO.md`](../TODO.md).

## Tests

- Test launches no longer leave copies of the app behind. At each launch Chromium clones
  the app bundle into `/var/folders/…/X/<bundle id>.code_sign_clone/`
  (`chrome/browser/mac/code_sign_clone_manager.mm`, so that an update staged while it
  runs doesn't break its code signature), and removes the clone when it quits normally;
  macOS clears the folder only at boot. Tests kill the browser, so every run left one,
  and each kept the blocks of a build since rebuilt: some 550 of them had filled the
  disk. `launch()` in `chromium/scripts/lib/oblada.mjs` now passes
  `--disable-features=MacAppCodeSignClone`.
- `smoke.mjs` checks, after its restart, that the restored tabs in the background stay unloaded
  until opened, and that a container tab discarded (as an extension's `tabs.discard()` would)
  reloads in its container. It reads and discards tabs through `oblada://discards`
  (`getOrCreateDetailsProvider()` from `discards.js`); discarding gives a tab a new id there.
