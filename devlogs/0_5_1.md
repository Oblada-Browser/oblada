# Oblada 0.5.1: devlog

Released on 2026-10-28. Based on Chromium 156.0.8078.48. What changed since 0.5.0, in detail; the
public release notes are in [`changelogs/0_5_1.json`](../changelogs/0_5_1.json).

## Safe Browsing gets its lists

- Safe Browsing never worked: Chromium downloads its lists from Google's Safe Browsing API
  with the build's Google API key, and Oblada's builds had none (`google_apis::GetAPIKey()`
  is a placeholder then), so Google refused every update. Settings still showed Standard
  protection on, and Chromium's warning that the keys are missing is turned off
  (`startup/infobar_utils.cc`).
- Releases now have a key of Oblada's own for the Safe Browsing API (v4, free for
  non-commercial use), given to Safe Browsing alone. Chromium's `google_api_key` would give
  it to every Google service it has (Translate, Optimization Guide, password
  affiliations…), which would start calling Google with it.
  - `oblada/components/safe_browsing/BUILD.gn`: the build argument
    `oblada_safe_browsing_api_key`, as a build flag (`buildflags.h`).
  - `sb_protocol_config.cc`: `GetSBProtocolConfig()` uses it when the build has one, for the
    lists' updates and full-hash lookups (`SBProtocolManagerUtil::GetRequestUrlAndHeaders()`,
    the only user of the config's `key_param`). Reports to Google keep `google_apis`' key,
    so they stay off. The patch to `components/safe_browsing/core/browser/db/BUILD.gn` gives
    `sb_protocol_config` the flag's header.
  - The key is in the maintainer's login keychain, "Oblada Safe Browsing API key"
    (`make safe-browsing-key` asks for it, once). `env.sh`'s `safe_browsing_key` reads it;
    `build.sh --release` writes it into `out/Release/args.gn`, and `release.sh` refuses to
    run without it. Development builds don't get it, so tests don't call Google.
- `smoke.mjs` checks it on builds with the key (`make test RELEASE=1`, with the network):
  Google's test page for phishing (`testsafebrowsing.appspot.com/s/phishing.html`) gets
  Safe Browsing's warning, in a profile of its own started with
  `--safebrowsing-fast-initial-lists-update` (the lists' first update 10-20 s after the
  start rather than 1-5 minutes).

## Security fixes, from an audit

An audit of Oblada's own code and its patches (2026-10-28) found holes, fixed here.

### Firefox add-ons

- Installs: an .xpi is installed only from addons.mozilla.org (`IsAddonSource()`: HTTPS,
  `addons.mozilla.org` or its files' host `addons.cdn.mozilla.net`), the whole URL chain
  and the initiator, if any (`IsAddonDownload()`); from anywhere else it's only a file.
  Until now any site could offer one, and Mozilla's signature isn't checked.
- `Install()` wrote the add-on's key and update URL (`oblada.firefox_addons.keys`,
  `.update_urls`) before asking: a page offering an .xpi with an installed add-on's
  gecko id, refused, still pointed that add-on's updates at its server, which then
  installed silently. They're saved in the installer's callback, once installed.
- Updates (`addon_updates.cc`): from addons.mozilla.org's API only (an `update_url`
  elsewhere is ignored), the downloaded file too (`GetFinalURL()`); an update whose
  manifest has another gecko id than the add-on's is refused (`Install()`'s
  `expected_id`).
- The .xpi is unpacked by Chromium's unzip service, in a sandboxed process
  (`unzip::Unzip()`), not by the browser process: at most 512 MB and 20000 files
  (`UnpackState`), checked against the archive's own sizes and as it's written.
  `xpi_conversion.cc` keeps the conversion (`Convert()`) and the filter
  (`ShouldUnpack()`).
- The prompt for a download without a tab goes to the download's profile's window only.
- Official builds ignore `--oblada-auto-confirm-addon-install` (which accepted every
  extension's prompt) and the tests' new `--oblada-addon-test-source=<origin>` (an origin
  taken as addons.mozilla.org's): `#if !defined(OFFICIAL_BUILD)`. `smoke.mjs` skips the
  add-on checks on official builds, and checks that an .xpi from another site, or linked
  from one, isn't installed, and that an update that is another add-on is refused.

### Navigations reopened by the browser

Three places reloaded a page with `LoadURLWithParams()` as browser-initiated, so the site
got the request as if the user had typed its address (SameSite=Strict cookies,
`Sec-Fetch-Site: none`), whatever page started it: cross-site request forgery.
- De-AMP (`de_amp.cc`): the original is opened as initiated by the AMP page
  (`initiator_origin`, `is_renderer_initiated`, its user gesture).
- Containers' "always open in" (`SiteAssignmentThrottle`): reopened with the initiator
  of the navigation, or the site that redirected to it (`NavigationInitiator`, through
  `ReopenInContainer()`); a typed address stays browser-initiated. A page may send its
  tab to a container without a click once every 10 seconds (`MayReopenWithoutGesture()`):
  each time opened a tab, so a page could open any number.
- Peek (`peek.cc`): initiated by the page with the link, with the user's gesture.
`smoke.mjs` checks that a page's script sending a tab to its container gets
`Sec-Fetch-Site: cross-site`, and can't do it again at once.

### Preloading in containers

Chromium prerenders pages and prefetches searches in the profile's own storage
partition, not the container's: a page in a container could load another in the
profile's cookies, and a prerendered page taken for a new tab left the container.
- `browser_web_contents_delegate.cc`: `IsPrerender2Supported()` is
  `kPreloadingUnsupportedByWebContents` for containers' tabs.
- `search_prefetch_service.cc`: no prefetch from them; `chrome_content_browser_client.cc`:
  no prefetched search served to them (`containers::IsContainerFrame()`).
`smoke.mjs` checks that speculation rules prerender nothing in a container's tab.

### The Barrier's filter lists

- Trusted scriptlets (which run what the rule says) only for uBlock Origin's and Brave's
  own lists (`raw.githubusercontent.com/uBlockOrigin/uAssets/`,
  `.../brave/adblock-lists/`), and only as the catalog built into Oblada says
  (`Lists::Permissions()`): the catalog is downloaded unsigned, and the lists with
  trust came from eight hosts, any of which could have run scripts in every page.
- `barrier_resources.mjs` marks every resource named `trusted…` as needing trust: uBlock
  Origin doesn't mark `trusted-prevent-xhr` (which answers requests with the rule's
  text), nor Brave `trusted_types.js`, so any list, or the user's filters, could use them.
- `$csp` rules lose `report-uri` and `report-to` (`WithoutReports()` in
  `engine_host.cc`): a list could have every page report its address. `smoke.mjs` checks it.
- Lists, subscriptions and Brave's data lists over HTTPS only, redirects too
  (`IsListUrlAllowed()`; plain HTTP from this computer, for tests).

### The Barrier's pages and requests

- The answers of its pages (blocked domains, sensitive sites, Google sign-ins) carried one
  token for the session, readable by a page served in a site's own origin (any
  `*.firebaseapp.com`): with it a site could answer for the user. `AnswerUrl()` and
  `TakeAnswer()` (`domain_block.h`) make a token for one answer to one page's address,
  used once, for an hour at most.
- `BarrierHost.AddCustomFilter()` takes a filter only from the page the browser started
  the element picker on (`ElementPickerSession`, a `DocumentUserData`), its primary main
  frame with an HTTP(S) host, once: other documents, without a host (about:blank, blob:),
  could add rules for every site. `StartElementPicker()` checks again whether picking is
  possible.
- Redirects: the request filter only saw a request's first address. `RedirectChecker`
  sits between each request's client and the filter: a navigation's redirect is a new
  request for the filter (its questions, debounce, blocking, forgetting bounces), at most
  20; another request's is checked against the lists, then followed by the network, so
  CORS's rules on redirects hold. A request whose tracking parameters were stripped is
  now checked too (it went on to the network unchecked). `ApplyRedirect()` updates a
  redirected request as the network service does, its network partition included (a
  debounced page kept the tracker's). `smoke.mjs` checks that a redirect to a blocked
  address is blocked.

### HSTS and Certificate Transparency

- HSTS: the Barrier made it apply to pages only (`kHstsTopLevelNavigationsOnly`), so that
  sites couldn't read it back as a cookie, which left other requests to HSTS hosts in
  plain HTTP. As Brave, it's now partitioned instead (`kObladaPartitionHsts`, patches to
  `transport_security_state.{h,cc}` and `url_request_http_job.cc`): what a host's
  responses say from inside another site's pages is kept under that site
  (`PartitionFor()`, `STSKey()`: a hash of the host and the top-level site), what it says
  under its own site holds everywhere, with the same keys as before (so the saved state
  stays, and sockets' checks without a partition see it). The preload list applies
  everywhere.
- Certificate Transparency, as Chrome has it (`kCertificateTransparencyAskBeforeEnabling`,
  in `chrome_feature_list_creator.cc`): Chromium leaves it to Chrome-branded builds. The
  logs' list comes with the PKIMetadata component. Not the Barrier's: on in any case.

### Settings for what's decided at startup

What the Barrier decides as Oblada starts had only its switch ("DANGEROUS"): each now has
its own, in Settings > Oblada > Privacy, "When Oblada starts", with Relaunch when one
changed (`StartupProtectionsChanged()`, the handler's `startupChanged`, fired as
`oblada-barrier-state-changed`). Local State prefs, all on: `oblada.barrier.partition_hsts`,
`.partition_connections`, `.web_apis_off`, `.referrer_cap`, `.cookie_expiry_cap`
(`AddFeatureOverrides()`); each needs the Barrier on.
