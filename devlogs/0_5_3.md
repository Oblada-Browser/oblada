# Oblada 0.5.3: devlog

Not released yet. Based on Chromium 156.0.8078.48. What changed since 0.5.2, in detail; the
public release notes are in [`changelogs/0_5_3.json`](../changelogs/0_5_3.json).

## Firefox add-ons: contentScripts.register()

- uBlock Origin 1.76 registers its scriptlets with Firefox's `contentScripts.register()`
  (`js/vapi-scripting.js`), which Chromium doesn't have: Manifest V3's
  `scripting.registerContentScripts()` takes files only, and neither it nor `userScripts`
  is available to Manifest V2. uBlock calls it for the tabs already open as it starts
  (`initializeTabs()` in `js/start.js`), before `webRequest.start()`: the
  `TypeError` there left it without network filtering at all, whenever it started with a
  web page open, as it always does once installed from addons.mozilla.org.
  `smoke.mjs`'s "uBlock Origin blocks ads" check failed on it.
- The compat script (`firefox_addons/compat_script.h`) adds `contentScripts.register()`
  to background contexts that have `tabs.executeScript()` and `webNavigation` (add-ons
  without the `webNavigation` permission still don't have it, and those checking for it
  do without, as before): each
  registered script runs, with `tabs.executeScript()` and `tabs.insertCSS()`, in the frames
  matching its `matches`, `excludeMatches`, `includeGlobs` and `excludeGlobs` as they
  commit (`webNavigation.onCommitted`), not in documents committed before it was
  registered (as in Firefox), `allFrames`, `runAt`, `matchAboutBlank` (and
  `matchOriginAsFallback`) and `cookieStoreId` as given. `world: "MAIN"` scripts are
  added to the page as a `<script>`, which the page's CSP can refuse. `unregister()`
  removes it. This is how uBlock injected scriptlets before 1.76, so they run as early as
  they did, not always before the page's own scripts as in Firefox.
- The compat script is written among an add-on's files when it's converted, so a newer
  Oblada's didn't reach add-ons already installed until their next version.
  `UpdateCompatScripts()` (`firefox_addons.cc`), called by `StartAddonUpdates()` once a
  profile is in use, rewrites the copy of each installed Firefox add-on that differs
  from this Oblada's and reloads it (`ExtensionRegistrar::ReloadExtension()`).
- `smoke.mjs`: the test add-on registers a script in each world ("Firefox add-ons register
  content scripts (contentScripts.register)"), and before the restart its compat script
  is replaced by an older one, which must be brought up to date ("Firefox add-ons get a
  newer Oblada's compat script as it starts").

## Firefox add-ons: event pages with webRequest

- Firefox lets a Manifest V2 add-on's background page be an event page
  (`"persistent": false`, unloaded when idle) and still use `webRequest`, waking the page
  for its events. Chromium refuses the pair (`BackgroundManifestHandler`, "The 'webRequest'
  API cannot be used with event pages."), so AdGuard's add-on, which blocks with
  `webRequestBlocking` from an event page, failed to install as an invalid package.
- `Convert()` (`firefox_addons/xpi_conversion.cc`) makes such a background page persistent
  when the add-on asks for `webRequest` in `permissions` or `optional_permissions`
  (`UsesWebRequest()`), with the warning "Its background page stays loaded".
- `smoke.mjs`'s test add-on is now an event page with a blocking `webRequest` listener:
  "Firefox add-ons block requests from an event page (webRequestBlocking)".
