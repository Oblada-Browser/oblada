# Oblada 0.4.1: devlog

Not released yet. Based on Chromium 156.0.8078.48. What changed since 0.4.0, in detail; the
public release notes are in [`changelogs/0_4_1.json`](../changelogs/0_4_1.json).

## Reload next to back and forward in the sidebar

- In the sidebar, the reload button is back next to back and forward, as in Zen, when the
  sidebar is wide enough for it (198 points, with the window controls); in a narrower one
  it's in the app menu, as it always was before.
- `oblada::sidebar::ShowIfRoomInSidebar()` (`oblada/browser/ui/sidebar_layout.{h,cc}`),
  replacing `HideInSidebar()`, gives the button a flex rule while the toolbar is in the
  sidebar: its preferred size or nothing (`kPreferredSnapToZero`), with the last flex order
  (`kLastFlexOrder`), so the toolbar's `FlexLayout` drops it before any other button,
  forward included, as the sidebar narrows. Out of the sidebar the rule is cleared, and
  the button is laid out as Chromium's.
- `toolbar_view.cc` calls it from `LayoutCommon()`, and gives reload the small insets of
  back, forward and the menu in the sidebar (`kButtonInset`, no margins).
  `oblada::sidebar::ArrangeButtonRow()` skips it when it's dropped, as it skips hidden
  views.
- `app_menu_model.cc`: "Reload" is in the app menu only when the toolbar doesn't show its
  button (`oblada::sidebar::ShowsReloadButton()`: drawn, with bounds), checked as the menu
  opens. So it's no longer there twice in the layouts with the address bar at the top,
  which always show the button.
- `smoke.mjs` checks it: reload right after forward in the sidebar, gone once the sidebar
  is dragged to its narrowest (170).
