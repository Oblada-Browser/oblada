# Oblada 0.4.2: devlog

Released on 2026-10-26. Based on Chromium 156.0.8078.48. What changed since 0.4.1, in detail; the
public release notes are in [`changelogs/0_4_2.json`](../changelogs/0_4_2.json).

## The sidebar keeps its width across restarts

- After a restart, the sidebar often opened at the default width (280) rather than the one
  it was dragged to. Each window saves its vertical tab strip's state (collapsed, width) in
  the session as window extra data (`vertical_tab_strip_collapsed`,
  `vertical_tab_strip_uncollapsed_width`), but only as it changes
  (`VerticalTabStripStateControllerImpl::UpdateSessionService()`). Chromium rebuilds the
  session file every 250 changes (`kWritesPerReset`), from the windows and tabs as they are
  (`SessionServiceBase::BuildCommandsForBrowser()`), and the rebuild left the state out. A
  window restored without it doesn't read the last width from the prefs either (only new
  windows do), so it got the default.
- `session_service_base.cc`: `BuildCommandsForBrowser()` writes the state into the rebuilt
  session too, from `tabs::VerticalTabStripStateController::From(browser)`.
- `browser_window_features.cc`: a window restored without its width (from a session saved
  by an earlier version) gets the last one used, `prefs::kVerticalTabsUncollapsedWidth`, as
  new windows do.
- `smoke.mjs` checks it: the sidebar is dragged narrower, the session rebuilt (enough
  `history.pushState()` calls), and Oblada restarted.
