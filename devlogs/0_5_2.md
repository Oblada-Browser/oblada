# Oblada 0.5.2: devlog

Not released yet. Based on Chromium 156.0.8078.48. What changed since 0.5.1, in detail; the
public release notes are in [`changelogs/0_5_2.json`](../changelogs/0_5_2.json).

## The Barrier: requests no longer wait for DNS each time

- CNAME uncloaking asked the container's resolver for the canonical names of every
  request's host on another site (`include_canonical_name`, which only the system's
  resolver gives), and the request waited for the answer. Chromium's host cache
  normally answers at once, but it forgets everything whenever the system's DNS
  configuration changes, and some networks change it all the time: on a FRITZ!Box's,
  macOS alternates its search domains (`fritz.box`, then also the router's
  `….myfritz.net`) a few times a second. Every request to another site then waited for
  the system's resolver, ~25 ms each in a NetLog of YouTube (`DNS_CONFIG_CHANGED` about
  3 times a second, most canonical-name lookups missing the cache): video segments
  from googlevideo.com, thumbnails, fonts. YouTube lagged with the Barrier on, and
  didn't with ad blocking off for the site, as Chromium's own requests reuse their
  connections without asking DNS. Requests to the page's own site weren't affected.
- `CanonicalNames` (`request_filter.cc`, on the engines' sequence) keeps each host's
  names for each container (its storage partition's path) and top-level site (the
  network anonymization key, as Chromium's host cache is split): requests wait only
  for a host not known yet, and lookups for the same one share the answer. Names over
  a minute old are still used and asked for again in the background; names not
  refreshed for an hour are forgotten; at most 4096 hosts. A lookup without an
  answer (cancelled, timed out) isn't kept: `CanonicalNameClient` now answers with
  the resolver's error, apart from a host without names.
- Chromium also stops every lookup under way when the configuration changes
  (`ERR_NETWORK_CHANGED`), and the request then went on unchecked: a slow lookup, as
  www.microsoft.com's long CNAME chain, often was, which made `smoke.mjs`'s CNAME
  uncloaking check fail now and then. `RequestFilter::Uncloak()` asks again, up to three
  times. The resolver reports most failures as `ERR_NAME_NOT_RESOLVED` (Chromium's
  `HostResolver::SquashErrorCode()`): `CanonicalNameClient` takes the error from the
  `ResolveErrorInfo`, else a stopped lookup would pass for a host without other names.

## Development

- `make free-space` (`chromium/scripts/free_space.sh`, `DRY=1` lists first): removes what
  development leaves outside the builds. Test runs' Oblada left running once their test
  was stopped (the test copy's main processes whose parent is launchd, found by their
  executable), their profiles and folders in the temporary folder (`oblada-*`, and
  add-ons unpacked there over an hour ago), the test apps' settings in `~/Library`,
  Oblada's code-sign clones in `/var/folders/…/X` no running process uses, and
  `/tmp/oblada*`. Never the builds' directories, the website's, the user's profile or its
  caches, nor releases' symbols; it refuses while a test, a build or a release runs.
