# Oblada 0.1.1: devlog

Released on 2026-10-20. Based on Chromium 155.0.8059.85. What changed since 0.1.0
(published as `155.0.8059.85-1`), in detail; the public release notes are in
[`changelogs/0_1_1.json`](../changelogs/0_1_1.json).

## Sidebar

- A downloads button at the bottom of the sidebar, before the workspaces, as in Zen
  (`oblada/browser/ui/downloads_button.h`). It's Chromium's toolbar button moved there
  (the `kActionShowDownloads` action): its progress ring, badge and bubble of recent
  downloads, which opens above it (`download_toolbar_ui_controller.cc`). It turns blue
  when a download has finished and hasn't been looked at yet. The toolbar's own no
  longer shows, nor the animation rising from the page to it.
- The bookmark star and the "install app" page action left the sidebar's address bar,
  which had room for little else (long addresses ended up as "..."). They stay in the
  view tree, out of layout, for what Chromium anchors to them
  (`oblada::site_panel::HidePageActionsInPanel()`). The site panel has them instead:
  - the star is filled, in the accent color, when the page is bookmarked;
  - a new tile installs the site as an app (`IDC_INSTALL_PWA`), or opens it in its app
    once installed (`IDC_OPEN_IN_PWA_WINDOW`).
  The panel's tiles are 44×44, five per row, so it keeps its width.
- Clicking the address bar shows the whole URL as it floats, not only the site:
  Chromium unelides it for the keyboard's focus but not for a click's
  (`LocationBarView::UpdateObladaFloating()`).
- Fixed: after the pointer passed over the quiet address bar, the site's icon could
  stay drawn above it. While its hover highlight fades, a button's icon is on a layer
  of its own; when the bar went quiet mid-fade, Chromium recreated the highlight,
  invisible and never removed, and the icon's layer stayed where the zero-sized button
  left it. What the quiet bar hides is now clipped to nothing, layers included.

## First launch and startup

- The first launch opens `oblada://welcome` instead of the New Tab page
  (`startup_browser_creator_impl.cc`). Chromium's first run window (signing in to
  Google) is marked as done in `PreProfileInit()`, so it never opens.
- No startup prompts over the welcome (restoring tabs, the default browser, PDFs); an
  obsolete system or dangerous flags still warn (`infobar_utils.cc`).
- The last session's tabs and workspaces come back at startup by default, as in Zen
  and Arc (`session_startup_pref.cc`); Settings' "On startup" can change it. The
  infobar offering it is off (`kSessionRestoreInfobar`).

## Settings and About

- Settings has no "You and Google" page (`page_visibility.ts`). Its routes go with it,
  Settings' import dialog included: "Import bookmarks and settings" opens the welcome's
  import (`oblada://welcome/#import`, `chrome_pages.cc`), which the welcome's data source
  now serves whatever follows its path.
- About Oblada (`oblada/browser/about/`):
  - "Version 0.1.1, based on Chromium 155.0.8059.85 (arm64)";
  - Oblada's copyright, and its source code on GitHub (GNU GPL v3);
  - help (the About page, the Help menu) opens the GitHub issues;
  - no update status (`about_handler.cc`): there's no updater, and Chromium's check
    failed with "error code 0".
- `oblada://credits` is generated at build time (`generate_about_credits = true` in
  `args.gn`): 758 projects with their licenses, instead of Chromium's sample page.
- `rebrand.py` keeps the name of the link to the Chromium project ("made possible by
  the Chromium open source project"), in every language.
- `oblada://version` shows Oblada's version and Chromium's (`version_ui.cc`).

## Versions and releases

- Oblada has a version of its own, apart from Chromium's: `chromium/oblada/VERSION`
  (0.1.0 until this release is cut). GN writes it into the generated `oblada/version.h`
  as `OBLADA_VERSION`, so a new version rebuilds only the files that include it.
- `release.sh <notes.md>` tags the release with the bare version (`0.1.1`) and names it
  "Oblada 0.1.1"; `dmg.sh` names the DMG after it (`Oblada-0.1.1-arm64.dmg`); the notes
  say which Chromium it's built on. The app bundle's Info.plist keeps Chromium's
  version: PWA shims find the framework by it.

## Tooling

- A `Makefile` over the scripts: `make` lists the commands (sync, build, patches, test,
  screenshot, dmg, bump, release, icons, run…). Written for macOS's GNU Make 3.81.
- `chromium/scripts/dmg.sh` and `release.sh`, committed after 0.1.0 was published with
  them; `branding/dmg/` draws the DMG window's background.
- The smoke test checks the first launch and the versions, and restores the last
  session with no flag. `lib/oblada.mjs` takes `firstRun: true`.
- Snapshots can hover a view: `--do="hover:<view class>"`.
- `CONTRIBUTING.md`: what a build needs, how to change Oblada's code and Chromium's
  files, test, and open a pull request. The disk sizes in the docs are measured:
  about 32 GB of sources and toolchains, 11 GB for a build without symbols (not 60).
- Logs per release: `devlogs/<x_y_z>.md` (this) and the public `changelogs/<x_y_z>.json`,
  which the website reads when it's generated; `changelogs/README.md` has the format.
